# W9：跨平台转录引擎（faster-whisper × Windows/Linux）

日期：2026-09-26 ｜ 前序：W8（whisper 型号×镜像×断点续传基建）｜ 类型：平台适配

## 1. 背景（Owner 裁定 2026-09-26）

- W8 起 whisper 步骤限定 darwin/arm64（mlx-whisper 无其它平台构建），
  Windows/Linux 转录整链跳过——静态总结失去核心输入（讲评语音内容）。
- Owner 拍板：**按平台选最优引擎，本地资源充分利用**：
  - darwin/arm64：保留 mlx-whisper（Apple Silicon 最优，CTranslate2 无 Metal）
  - Windows/Linux：faster-whisper（CTranslate2；pip 即装、CPU int8 快、
    有 N 卡可 CUDA、模型走 HF 镜像+断点——复用 W8 基建）
- 网易 Confucius4-R2T2 等「真流式 ASR」不在本期（Owner 后续 WebRTC 实时
  转录另立项）；引擎层设计留插拔位，实时引擎未来按策略项接入。

## 5. 顺延修复（2026-09-27，Owner Windows 实测反馈）

- 现象：Windows 直接点 whisper 模型下载 →「[失败] huggingface_hub 未安装
  （uv sync --extra transcribe）」（日志乱码为 GBK 控制台显示 UTF-8）。
- 根因：依赖时序——warm runner 与管线 runStep 都假设 python-env 步骤先跑过
  `uv sync --extra transcribe`；用户跳过它时 venv 缺 huggingface_hub，
  warm_whisper 的探测分支退出 3（mac 按序走步骤从未暴露）。
- 修复三件：
  1. warm_whisper 去 huggingface_hub 依赖：元数据查询改标准库直调 REST
     `GET /api/models/{repo}?blobs=true`（与 hf_hub model_info 同一端点），
     字段映射注意 REST 是 `blobId`/`lfs.sha256`（hf_hub 客户端重命名为
     `blob_id`/`lfs.oid`）——已与 hf_hub 逐文件交叉验证等价。warm 从此
     纯标准库零 venv 依赖。
  2. warm runner 与管线 runStep 的 `uv run` 均加 `--extra transcribe`：
     步骤乱序自愈（uv run 只补缺不卸载——mac 管线裸 uv run 数月未卸 mlx
     为实证；与 uv sync 的 exact 语义不同）。
  3. 两处 python 子进程 spawn 统一 `PYTHONUTF8=1`：Windows 控制台 GBK 下
     python 输出按代码页编码、daemon 按 UTF-8 解码导致 last_log 乱码。
