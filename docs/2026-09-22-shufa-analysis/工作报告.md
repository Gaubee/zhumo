## 〇、迭代记录（Owner 反馈驱动）

### 第二轮：方向修复 + 回放视频（2026-09-22 晚）

1. **田字格裁剪方向错误（根因不是全局旋转）**：讲解时间线（矩形裁剪）方向正确、
   田字格一览与焦点大图（透视裁剪）方向错误——差异指向透视变换本身。
   根因：`approxPolyDP` 输出的角点顺序取决于轮廓追踪方向（外/内轮廓、起点任意），
   直接喂 `getPerspectiveTransform` 会随机镜像/旋转。修复：`order_quad_tl` 以
   min/max(x+y, y−x) 规范四角为 [左上,右上,右下,左下]。修复前后对比图经 vision
   判读：三张 OLD 全部 180° 倒置，三张 NEW 全部正立（木旁在左，杨/桂/树确认）。
   经验：**凡 getPerspectiveTransform 的输入四边形，角点必须规范化**；
   "部分产物方向错、部分对"时优先怀疑变换路径差异而非全局朝向。
2. **动态讲解效果**：新增 `clips.py` 模块——ffmpeg 单遍 `transpose→crop→scale`
   从源视频直出焦点区剪辑（30fps、H.264+AAC 保留讲解原声），base64 内嵌。
   子代理交付时用"源帧 cv2 转正裁剪 vs 剪辑同帧"对比验证几何正确性（平均绝对
   差 2.38，纯编码损失量级）。

### 第四轮：Vite HTTP 服务化 + 裁剪精化 + 播放器 Popover（2026-09-22 深夜）

4. **旁注簇标定**：角点精化后格框收紧，近格过滤半径随之标定（欧氏 2.6 格
   边长：保留 15s 长横线 189px、排除 6s 语义不明晕染团 231px），旁注定稿
   3 处（9.0s △△方框记号 / 15.0s 长横指示线 / 28.5s 圭），标签对位。

### 第三轮：动态学习版（2026-09-22 深夜，Owner 三点新需求）

1. **脱离原生控件的自定义播放器 + 同步时间轴**（`player.py`，子代理交付）：
   自绘控件（播放/拖拽进度/倍速/循环/静音），进度条带菱形关键帧标记（可点击），

   （用户手动滚动后 4s 内不打扰）、每条字幕有独立背景进度（scaleX 实时填充）、
   点击任意条目跳转。headless Chrome 7/7 交互场景自测两轮稳定（seek/点击标记/

4. **音画增强（默认开启）**：音频 `afftdn` 降噪 + `loudnorm` EBU R128 响度归一

   决策依据：单遍低成本滤镜、代价一次性且远低于跑模型，符合"算力合理则默认开"。

### 第二轮：方向修复 + 回放视频（2026-09-22 晚）

Owner 验收指出两个问题，均已修复并实证：

1. **田字格裁剪方向错误（根因不是全局旋转）**：讲解时间线（矩形裁剪）方向正确、
   田字格一览与焦点大图（透视裁剪）方向错误——差异指向透视变换本身。
   根因：`approxPolyDP` 输出的角点顺序取决于轮廓追踪方向（外/内轮廓、起点任意），
   直接喂 `getPerspectiveTransform` 会随机镜像/旋转。修复：`order_quad_tl` 以
   min/max(x+y, y−x) 规范四角为 [左上,右上,右下,左下]。修复前后对比图经 vision
   判读：三张 OLD 全部 180° 倒置，三张 NEW 全部正立（木旁在左，杨/桂/树确认）。
   经验：**凡 getPerspectiveTransform 的输入四边形，角点必须规范化**；
   "部分产物方向错、部分对"时优先怀疑变换路径差异而非全局朝向。
2. **动态讲解效果**：新增 `clips.py` 模块——ffmpeg 单遍 `transpose→crop→scale`
   从源视频直出焦点区剪辑（30fps、H.264+AAC 保留讲解原声、436×360、431KB、
   截到平静区间避开片尾翻页），base64 内嵌 HTML 的 `<video controls loop>`，
   实现可控可重播的动态讲解。子代理交付时用"源帧 cv2 转正裁剪 vs 剪辑同帧"
   对比验证几何正确性（平均绝对差 2.38，纯编码损失量级）。
   顺带把旁注卡片排版理整齐（统一图高、时间徽章、描述层级）。

## 三、方案与关键取舍

### 1. 旋转探测：几何统计而非深度模型
容器无 metadata 时需从画面推断朝向。迭代三版后的方案：**纸面墨迹行投影的 FFT
谱峰占比**（行距滞后带 25~95px 的最大功率 / 总功率）。正确族 0.12~0.17 vs
错误族 0.015~0.03，5~8× 分离。两个被证伪的中间版本值得记录：
- 高频 std：被牛皮纸板斜边、桌面交界等**锐利孤立边缘**虚假抬高（0.21 vs 0.07，方向反）；
- 自相关 max：对噪声不鲁棒。
教训：**"文字行周期性"必须用谱峰占比度量，且只统计纸面亮连通域内的中等灰度墨迹**。
180° 步进对任何行投影统计都无判别力（周期性翻转不变），用领域启发式补刀：
拼音标签带在格上方（单帧 + 多数票 + 置信度门槛）。取舍：通用性让位于本领域
（按拼音写词练习册）的确定性；无拼音页面退化为 `--rotate` 手动指定。

### 2. 田字格检测：OpenCV 规则管线，明确不用 SAM3
实测驱动的三个决策：
- **格框几何取自锐利单帧而非合成背景**：即使相位相关对齐后，亚像素残差仍把
  1px 印刷线洗掉（顶边命中率仅 11%）。多帧投票（锐度 top7 + 首末帧）+ NMS 合并。
- **NMS 用包含感知重叠度**（inter/min_area）：杨格内曾出现 34px 假阳性内框，
  标准 IoU=0.2 漏杀，包含感知下 1.0 必杀。
- **无手帧降权**：手入镜增加边缘数、污染四边形（桂格框 82px vs 真实 75px），
  候选得分按手活动量（高饱和暗像素数）降权。
SAM3/sam3-mlx 经调查确认不引入：FP16 单图约 8-10GB 统一内存，macmini swap 已
9.4/10GB；且规则印刷网格是确定性任务，OpenCV 毫秒级、零模型内存、结果可解释。

### 3. 对齐：相位相关平移，不做整页单应性校正
手持漂移实测 dx −8.5~1.8px。平移对齐解决了背景合成洗线与差分双影；页面约 2°
的透视倾斜对透视裁剪（warpQuad）影响很小，整页文档校正（docTter/UVDoc 类）
对平放作业本属于过度设计，不引入。

### 4. 旁注提取：本任务最难的部分，四层过滤 + 一个语义先验
铅笔笔迹对比度仅 5~15 灰阶，是整条管线物理上最脆弱的环节。实测踩坑与对策：
| 干扰源 | 表现 | 对策 |
|---|---|---|
| 静态印刷体 | 末帧差分全是字 | 背景最大合成 + 首帧静态掩码排除 |
| 手/黄铅笔杆 | 22k px 假簇 | 低饱和过滤（灰笔迹 S<60，皮肤/笔杆高饱和） |
| 手阴影 | 低饱和灰、扫过 | 大块剔除 + 复现≥4帧 |
| 自动曝光 | 纸面灰度 172~188 波动，开场暗帧整页误报 | 逐帧纸面灰度加性归一化 |
| 笔迹闪烁 | 同一像素对比度 6↔94，AND 持久化把真笔迹整段抹掉 | 复现≥4帧（OR 聚假、AND 抹真之间的中间点） |
| 翻页/移镜 | 末帧全页差异 16 万 px，污染簇与首现 | 平静区间截断（原始动态量 >12000px 判运动） |
| 纸板视差边缘 | 复现噪声 | 近格语义过滤（旁注必在格 2.2 边长内） |
最终 4 个旁注簇，首现时间 6.0/9.0/15.0/28.5s，与转录教学节点（9s 左右结构、
15s 上下对齐、28s 纠正）吻合。

### 5. 转录与摘要：本地 whisper + 可插拔语义层
mlx-whisper large-v3-turbo（模型 ~1.7GB 缓存后秒级转录），附书法教学同音字修正表
（"柜子"→"桂字"等）。**摘要分两层**：CLI 内置规则摘要（关键词命中，任何环境可跑）；
`--summary-file` 注入精修摘要（本次交付用 transcript + vision 事实人工精修）。
旁注的语义解读（△△ 强调部件、长横线提示对齐）同理经 `--labels` 注入——CV 层
只负责"有什么、何时出现"，"是什么意思"交给语义层，边界诚实。

## 五、更好的方案（按投入产出排序）

1. **端侧 VLM 一站式语义层**（推荐下一步）：Qwen-VL 类模型对本任务可一次完成

4. **整页单应性校正 + 光照平场**：拍摄角度大、阴影重的场景收益明显；
   当前场景（近正拍、均匀光）收益小。
5. **置信度全链路输出**：每格/每簇给 confidence，低置信走人工复核 UI，
   适合批量跑录播课场景。
